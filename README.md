# MiniMax-H3 particle sliders

**Experimental source publication.** Synthetic/software CPU evidence only. Historical UNI and the guarded modern shared-session candidate stay separate. No native/GPU/media/quantized quality qualification is established; wide-vector admission still refuses.

See [PUBLICATION.md](PUBLICATION.md) for sanitation, lineage and current CPU/CI limits.


Standalone H3-family product extracted from reviewed
`HyperGAN/particle-sliders@fae34ef80f8ad0fbe02e5d9abc3c0e770798d5f7`.
Public source destination: `HyperGAN/minimax-h3-particle-sliders`.
Publication covers code only, not model weights, training admission or deployment. The original extraction preserved runtime modules, data and namespaces. The
modern shared candidate now deliberately adopts a new source cohort, described
below; legacy UNI, native model behavior and model identities stay unchanged.

There are two distinct lanes:

| Lane | Status |
| --- | --- |
| [Historical MiniMax-H3 UNI](docs/minimax-h3-slider.md) | Preserved supervised recipe and custom adapter format; not relabeled as shared GAN training. |
| [Pika H3 Flex native boundary](docs/pika-h3-flex.md) | Local pinned loader, fixed release adapter at 1 and independent slider; pretrained/GPU/media/quantized execution unqualified. |
| [Pika shared-session candidate](docs/pika-h3-flex-shared-session.md) | Actual installed shared PG lifecycle and HyperGAN/HNDL graphs; native wide-vector admission refuses before loading. |

This repository owns H3 loading, packing, adapters, graphs, configs and tests.
Generic lifecycle, ParticleGAN mathematics, checkpoint utilities and the verified
HyperGAN/HNDL builder stay in the installed shared library. No shared-core source,
weights, vendor environments, credentials or generated training outputs are copied.

## Isolated installation

Python >=3.11 is required. Install a built wheel in an isolated H3 environment.
The `native` extra records the exact reviewed Diffusers commit; its other
dependencies are compatibility ranges, not a complete reproducibility lock.
Native loading also verifies the pinned source hashes and local model manifests.

The optional `shared` lane still requires the separately qualified **candidate**
core 0.12.0 at `a794e3b4a8813b012f2c4faa3da82b78d4a90214`, with PG0.9.4,
HyperGAN develop `5f368a3770cf5bdae0448995c9f76e29af8049f7` and HNDL0.10.0.
The optional dependency URL pins that exact commit, and
`data/pika-h3-flex-session.json` verifies the complete 50-file package source
closure. A version number alone does not satisfy it. The prior candidate
cohort remains preserved locally and its artifacts are refused by the new cohort
without metadata rewriting. No runtime dependency installer is added.

Installed commands are `h3-flex` (provenance/admission/gradient probe),
`h3-legacy-uni` and `h3-legacy-diag`. Their `--help` is safe and does not load
models. Shared sessions remain explicit Python API calls; no new training or
default backend registration is introduced.

```bash
h3-flex provenance
h3-legacy-uni --help
python -m pytest --import-mode=importlib tests
```

Use installed packages when testing; do not add another product checkout or an
umbrella `src` directory to `PYTHONPATH`. The package intentionally retains the
`conceptmod.textsliders` namespace for compatibility. Do not co-install another
distribution owning those same modules in this isolated environment.

## Extraction and qualification

[Extraction notes](docs/extraction.md) describe the explicit allowlist,
blob-level provenance, packaging changes and installed-artifact tests.
`conceptmod/textsliders/data/h3-extraction.json` records original paths and blobs.
The Pika docs and JSON receipts retained from the original head are historical
evidence; their old repository paths and test counts describe that source snapshot.
Current local extraction validation is recorded separately. The [shared-core
adoption note](docs/extraction.md#deliberate-shared-cohort-update) records the
subsequent candidate-only source change.

All software qualification uses tiny/synthetic CPU fixtures. The official
native response widths are 1,398,528 (480p) and 3,593,664 (768p), both refused
by the current official continuous-vector gate. GGUF is an unqualified inference
candidate, not a supported input or proven training path. Nothing here qualifies
pretrained loading, GPU fit, audiovisual quality, quantized training or deployment.
